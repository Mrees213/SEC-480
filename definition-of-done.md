# Definition of Done

Project 1 is complete when:

- GitHub issues exist for the major pieces of project work.
- Each issue has an owner, date, description, and is attached to `Milestone_01`.
- This definition of done is written before the analysis work begins.
- Project instructions have been tested using a verbatim read-back.
- An output contract has been written before the AI analysis is generated.
- The supplied evidence packet has been analyzed against one stated question.
- The critique uses the columns `id`, `claim`, `evidence`, `type`, and `verdict`.
- Every evidence cell contains either a verbatim quotation from the supplied evidence or `NO EVIDENCE`.
- Every `type` value is exactly `stated`, `inferred`, or `unsupported`.
- The analysis contains a section headed exactly `Cannot determine from this evidence`.
- A finding has been written for a reader who will not read the underlying evidence.
- Factual sentences in the finding are connected to supported claim rows using `[C#]` tags.
- A reusable Skill has been created.
- The Skill has been tested against different evidence without editing the Skill.
- A cross-system prediction has been written before the chain is tested.
- The actual result of the chain has been documented.
- Completed GitHub issues are closed by commit reference.
- The work is submitted on a branch through a pull request with the instructor requested as reviewer.
